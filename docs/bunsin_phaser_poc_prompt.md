# 분신 키우기 — Phaser PoC 구현 지시 (Claude Code용)

한국어로 보고한다. 코드 식별자는 영어.

## 0. 목표와 판정

- **목표:** Phaser 3 웹 PoC를 만들어 **핵심 컨셉과 뾰족한 재미**가 느껴지는지 사용자가 직접 플레이해 검증한다. 재미 판정은 사용자가 한다. 너는 "재미있다"고 판정하지 않는다.
- **검증 대상 5개**
  1. 첫 분신이 10초 안에 나온다.
  2. 같은 얼굴이 화면을 채우는 감각, 그리고 1~3분 안의 마을 공개 줌아웃.
  3. 첫 월급날 연출(첫 세션 4분).
  4. 고용·팀 보너스(단체 사진)에서 숫자와 분신이 터지는 손맛.
  5. 이사(명성·정착금)로 더 빠르게 다시 시작하는 쾌감.
- **자원 배분:** 시스템 구현에 쓴다. 비주얼·에셋에는 쓰지 않는다(§4).
- **환경:** 클라우드 세션이다. 사용자 PC가 없다. GUI 실행·실기 측정은 불가하다.

## 1. 절대 규칙

1. 기획서(`docs/bunsin-gdd.md`)에 적힌 게임 기능을 **생략·축소·임의 변경하지 않는다.** 못 만든 것은 조용히 빼지 말고 최종 보고에 '미구현 + 이유'로 적는다. 시간·토큰이 모자라면 §6 뒤쪽 마일스톤부터 미구현 처리한다. 앞쪽을 줄이지 않는다.
2. **핵심 기획은 바꾸지 않는다:** 재화 구조(돈·명성·통장·개성 분신, 새 화폐 금지), 성장 공식, 이사/명성, 수익화(확률 상품 없음, 강제 광고 없음), 설계 원칙 §1.2의 8개(합체 없음, 손해 없음 포함). 기획서와 충돌하거나 모순되는 지점을 만나면 기획서 해석대로 두고 보고한다.
3. 경제 수치는 코드에 박지 않고 `data/economy_v0.2/*.csv`에서만 읽는다. CSV 값이 기획서 본문 숫자보다 우선한다.
4. 기획서에 정의가 없거나 모호한 것은 §7의 기본값을 쓴다. §7에도 없으면 가장 단순한 해석으로 구현하고 `ASSUMPTIONS.md`에 한 줄 기록한다. 멈춰서 물어도 되는 경우는 핵심 기획과 충돌할 때뿐이다. 형식은 선택지 2~3개 + 추천 1개 + 이유 한 줄, 한 번에 최대 3건.
5. 실행하지 않은 것을 "검증 완료"라고 쓰지 않는다. 돌린 명령과 결과를 적는다.
6. 기획서에 없는 기능·화폐·화면을 추가하지 않는다. 검증용 디버그 도구(§5)만 예외다.
7. **토큰 절약:** 코드·로그를 길게 출력하지 않는다(테스트는 dot reporter, 빌드는 조용히). 바뀌지 않은 파일을 다시 읽지 않는다. 서브에이전트는 쓰지 않는다. 기획서는 처음 한 번 읽고, 이후에는 §번호로 필요한 부분만 찾아 읽는다. 스크린샷은 실패 원인 확인 때만 쓴다.

## 2. 시작 순서 (첫 작업)

1. 입력 파일을 repo에 준비한다. Projects 도구(`project_read`)가 있으면 아래 파일을 **내용 수정 없이** 그대로 복사한다. 없으면 사용자가 첨부한 파일을 쓰고, 둘 다 없으면 멈추고 요청한다.
   - `claude-code/bunsin-gdd.md` → `docs/bunsin-gdd.md`
   - `data/economy_v0.2/{cities,jobs,economy,account,milestones}.csv` → 같은 경로. v0.1은 쓰지 않는다.
2. `docs/bunsin-gdd.md`를 끝까지 한 번 읽는다. 기준 문서는 사용자의 "최종 기획서" 아티팩트이고 이 파일은 파생본이다. 이 파일과 CSV가 어긋나 보이면 구현을 멈추지 말고 CSV를 따른 뒤 보고한다.
3. `CLAUDE.md`를 30줄 이내로 만든다(이 지시서 §1 규칙 요약 + 파일 위치 + 명령어). 긴 세션에서 규칙이 잊히지 않게 하기 위함이다.

## 3. 기술 스택과 구조

- Vite + TypeScript + **Phaser 3(최신 3.x 안정판)** + Vitest + `vite-plugin-singlefile`.
- CSV는 `?raw` import로 번들에 넣는다. 파서는 직접 작성한다. UTF-8 BOM, CRLF, 따옴표 안의 쉼표, `1.260E+17` 표기를 처리해야 한다. 로드 시 일관성을 검증한다(§6 M0).
- 큰 수는 JS `number`로 충분하다(최대 약 2.4e67 수준). `Infinity`/`NaN` 가드만 둔다. 한국식 단위 포맷터는 별도로 만든다(만 1e4, 억 1e8, 조 1e12, 경 1e16, 해 1e20, 자 1e24, 양 1e28, 구 1e32, 간 1e36, 정 1e40, 재 1e44, 극 1e48, 항하사 1e52, 아승기 1e56, 나유타 1e60, 불가사의 1e64, 무량대수 1e68). 표시는 상위 두 단위까지, 새 단위가 처음 나오면 개그 한 줄을 띄운다(§2.7).
- **구조 (경제 계산은 Phaser와 완전히 분리):**
  - `src/core/` — 순수 TS, Phaser import 금지. 상태, 고용가, 수입, 월급날, 오프라인, 통장, 이사, 추천/ETA, 직렬화.
  - `src/data/` — CSV 로더·검증, 콘텐츠 표 로더.
  - `src/scenes/`, `src/ui/`, `src/fx/` — 화면과 연출. **씬 안에 경제 수식을 두지 않는다.** core의 액션/셀렉터만 호출한다.
  - `src/debug/` — §5.
  - `tests/` — core 단위 테스트.
- **시간 모델:** `tick(state, dt)`는 고정 스텝이다. 오프라인·배속 시뮬은 수입이 구간별 일정하다는 점을 이용해 이벤트 경계(월급날, 피버 종료, 해금)까지 한 번에 계산한다. 초 단위 루프로 30일을 돌리지 않는다.
- **저장:** localStorage에 자동 저장하고 `try/catch`로 감싼다(iframe/artifact 환경에서 막힐 수 있음). 막히면 메모리로 동작한다. 종료 시각을 저장하고 복귀 시 오프라인 정산을 계산한다.
- **화면:** 논리 해상도 360×640 세로, `Scale.FIT` + 자동 센터, 터치·마우스 모두 지원. 폰트는 시스템 폰트 스택(`"Noto Sans KR","Apple SD Gothic Neo","Malgun Gothic",sans-serif`)을 쓴다. 웹폰트 불가.

## 4. 비주얼·에셋 규칙 (최소)

- 이미지·오디오 파일 없음. Phaser `Graphics`/`Text`와 코드로 만든 텍스처(`generateTexture`)만 쓴다.
- **분신 = 같은 얼굴 원 + 점 두 개**를 풀링한 스프라이트로 쓴다. 직종/등급은 몸통 색으로만 구분한다(알바·직장·사업·투자 = 4색, 고용 시트·마을 구역·도감이 같은 색). 본체는 더 큰 같은 얼굴(표정 3종: 기본·일하는·환호). 화면 표시 상한을 둔다(예: 홈 150, 마을 300 → 넘으면 실루엣 점과 숫자 라벨로 묶는다).
- 건물은 색 사각형 + 직종명 + 인원 텍스트. 만화 컷은 전체 화면 텍스트 카드(낙서풍 테두리 사각형)로 대체한다. 사진은 화면 스냅샷(`renderer.snapshot`)을 작게 줄여 저장한다(앨범 최대 30장).
- 효과음은 WebAudio 오실레이터 수십 줄로 4종만 만든다(탭, 뿅, 월급날 '띵', 피버). 끄기 옵션을 둔다.
- **연출은 아래만 신경 쓴다(tween 위주, 각각 짧게):**
  - 분신 뿅: 거울에서 튀어나오는 오버슈트. ×10은 동시 점프.
  - 탭: 숫자 팝업, 본체 눌림.
  - 마을 공개 줌아웃: 카메라 줌 + 분신들이 골목으로 뛰기.
  - 월급날: 10초 카운트다운 → 플래시 → 사각형 월급봉투 흩날림 → 큰 숫자 카운트업.
  - 피버: 3단계 색 변화 + 분신 바운스.
  - 팀 보너스: 화이트 플래시 + 단체 사진 프레임.
  - 이사: 분신들이 트럭 사각형으로 이동.
- 그 외 화면은 기능만 보이게 하고 예쁘게 만들지 않는다.

## 5. 검증용 디버그 도구 (정식 UI와 분리, `?debug=1` 또는 숨은 영역 3탭)

게임 로직은 바꾸지 않고 core API만 호출한다.

- 시간 배속 ×1·×10·×60·×600.
- "N시간 오프라인 시뮬"(정산서까지 확인).
- 돈 ×10·×1000 지급, 월급날 즉시 발생, 매니저/통장 즉시 해금, 도시 N 점프(이전 꼭대기 첫 고용 상태 생성).
- 기기 시각 오버라이드(밤 11시 숨은 조건 테스트).
- 세이브 초기화.
- **지표 로그(§8.1):** 무반응 시간, 벽 노출, 사건 놓침, 마무리 카드 수, 배당 비중, 페이싱 시점(첫 분신·마을 공개·첫 월급날·사무실·매니저·가게·첫 이사의 누적 플레이 시간). 화면 오버레이 + JSON 내보내기.

**PoC에서 의도적으로 제외하는 것(미구현 아님, 보고에 한 줄로 명시):**
- 푸시 알림, 클라우드 백업, 랭킹/서버 시각.
- 실제 광고·결제 SDK. 정산서의 보상형 광고 2배는 1초 가짜 시청 연출로 대체하고, 상점은 항목만 두고 비활성 "PoC 미지원"으로 표시한다.
- 이미지·사운드 파일 에셋, 코스메틱.
- 콘텐츠 대량 작성. 사건 카드 8장·뉴스 10줄·분신 대사·공제 항목 소수만 임시 문구로 CSV에 둔다. **콘텐츠 CSV 열 구성은 기획서에 미정이므로 임시 구성(예: `id,type,text,choice_a,result_a,choice_b,result_b,series,next`)을 `docs/`에 한 줄로 기록**한다. 로더만 정상 동작하면 된다. 수량 확장은 CSV 줄 추가만으로 되어야 한다.

## 7. 기획서에 정의 없는 항목의 기본값 (바꾸려면 ASSUMPTIONS.md + 최종 보고에 표시)

각 항목은 한 곳에서만 정의하고 `core/assumptions.ts`에 모은다. 스위치로 바꿀 수 있게 한다.

| # | 항목 | 기본값 |
|---|---|---|
| A1 | 명성 합성 | 수입 = 직종 기본 × 팀 보너스 × 자격증 × (1 + 0.2 × 총 명성) × 피버(3) × 개성 패시브. 이사 시 명성 += `floor(√(그 도시 누적 수입 ÷ fame_unit))`, 총 명성 = 도시별 합 |
| A2 | 월급날 보너스 | 등급별 (지난 월급날 이후 그 등급 직종이 번 돈 × `payday_share`)의 합, 하한 = 초당 수입 × 120. 탭·통장·오프라인 수입은 제외, 피버는 포함 |
| A3 | 오프라인 월급날 | 오프라인 구간의 30분마다 같은 공식(오프라인 수입 기준)으로 계산해 밀린 월급봉투로 쌓는다. 매니저 해금 카운트에는 접속 중 월급날만 센다 |
| A4 | 상한 이후 오프라인 속도 | 상한(28,800초) 이후에는 모든 등급 0.25 |
| A5 | 통장 자동 적립 | 초당 수입의 10%를 현금에서 떼어 지금 종목에 넣는다. 한도(초당 수입 × 7,200) 도달 시 적립 중단. 한도가 차면 배당은 현금 |
| A6 | 자격증 | 해당 직종 보유 인원이 N(25·50·100·150·250·400) 이상이면 열린다. 가격 = `base_cost × growth^(N+10) × 4` |
| A7 | 추천 구매 | 구매 비용 ÷ 수입 증가량이 가장 작은 것(자격증 포함). ETA = (비용 − 현금) ÷ 초당 수입. 벽 = ETA ≥ 180초 |
| A8 | 목표 바 | 90초 이내 ETA의 가장 가까운 목표(없으면 가장 짧은 ETA). 새 목표는 15% 채워 시작하며 표시용이고 실제 돈은 안 준다 |
| A9 | 매니저 | 접속 중에만 작동. 1초마다 추천 구매 1회(자금 있으면), 피버 게이지가 차면 자동 발동. 오프라인 자동 구매 없음 |
| A10 | 사건 보상 | 초당 수입 × 30~120초 현금. 손해 없음 |
| A11 | 개성 분신 8종 | GDD 5종(야근왕=밤 11시 접속, 확성기 분신=피버 연속, 첫 월급날, 팀 보너스 25명, 분신 100명) + 임시 3종(첫 자격증, 통장 개설, 출근 도장 3일) |
| A12 | 이사 후 | 새 도시 첫 목표를 일부 채운 채 시작(A8), 통장 새 종목 열림, 정착금 지급 |

## 8. 테스트와 검증 규칙

- `npm test`(Vitest)로 core를 검증한다: CSV 검증, 고용가·팀 보너스·자격증 가격, 해금 체인, 월급날 하한, 오프라인 상한/속도, 통장 적립·배당·한도·깨기 순서, 이사 초기화/유지, 명성 공식, 큰 수 포맷 경계(만→억→조→경).
- 빌드: `npm run build`가 성공하고 `dist/index.html`이 단일 파일이어야 한다.
- 헤드리스 브라우저 스모크 테스트(Playwright 등)를 설치해 본다. 설치가 막히면 시도했다고만 적고 **"UI 실행 미검증"**으로 보고한다. 되면 부팅 → 첫 탭 → 고용 → 월급날 디버그까지 오류 없이 도는지만 확인한다.
- 저사양 Android 프레임, 연출 품질, 재미는 검증할 수 없다. "사용자 플레이테스트 항목"으로 넘긴다.

## 9. 전달

- git 브랜치 `poc/phaser`에 마일스톤별 커밋(메시지 한 줄)한다.
- **M3 완료 시, 그리고 최종 완료 시** 빌드(`dist/index.html`)를 사용자에게 전달한다. 가능한 수단(SendUserFile → 비공개 Artifact → GitHub Pages) 중 하나를 쓴다. artifact/iframe 환경에서도 돌아야 하므로 외부 CDN·네트워크 의존이 없어야 한다.
